# LinkBase Coding Rules

## 1. 总体设计原则

### 1.1 架构原则

LinkBase 必须遵循以下架构原则：

* **前后端职责明确**

  * Vue 负责 UI、状态管理、交互
  * Rust 负责数据库连接、查询执行、性能敏感逻辑
  * 禁止前端直接处理数据库协议逻辑

* **模块边界清晰**

  * packages 之间只能通过公开 API 通信
  * 禁止跨模块直接引用内部实现
  * 每个 package 必须具备独立可维护性

* **高性能优先**

  * 大数据量必须使用虚拟滚动
  * 查询必须异步执行
  * 所有数据库 IO 必须非阻塞
  * 禁止同步阻塞 UI

* **跨数据库统一抽象**

  * 所有驱动必须实现统一 `DbDriver`
  * 前端不得感知底层驱动差异
  * SQL 方言差异必须封装在驱动层

* **桌面应用稳定性优先**

  * 禁止未捕获 panic
  * IPC 必须做错误边界处理
  * 所有异步任务必须支持取消

---

## 2. Monorepo 规范

## 2.1 Package 结构规范

每个 package 必须遵循：

```text
packages/{module}/
├── src/
│   ├── components/
│   ├── composables/
│   ├── stores/
│   ├── services/
│   ├── types/
│   ├── utils/
│   └── index.ts
├── package.json
├── tsconfig.json
└── vite.config.ts
```

---

## 2.2 模块职责规范

| 模块         | 允许职责           | 禁止职责    |
| ---------- | -------------- | ------- |
| core       | 状态、API、路由、i18n | UI业务实现  |
| components | 通用UI组件         | 业务逻辑    |
| editor     | Monaco集成、SQL编辑 | 数据库连接   |
| result     | 表格展示           | SQL执行   |
| connection | 连接配置管理         | 查询解析    |
| schema     | 元数据展示          | 执行数据库变更 |

---

## 2.3 依赖方向规则

允许：

```text
业务模块 -> core
业务模块 -> components
```

禁止：

```text
core -> editor
core -> result
components -> core
```

禁止循环依赖。

---

# 3. TypeScript 规范

## 3.1 基础规则

必须开启：

```json
{
  "strict": true,
  "noImplicitAny": true,
  "strictNullChecks": true
}
```

禁止：

```ts
any
```

优先：

```ts
unknown
```

---

## 3.2 类型定义规范

### 禁止内联复杂类型

错误：

```ts
const state: {
  id: string
  name: string
}
```

正确：

```ts
interface ConnectionState {
  id: string
  name: string
}

const state: ConnectionState
```

---

## 3.3 类型文件位置

公共类型：

```text
src/types/
```

模块私有类型：

```text
当前模块文件顶部
```

---

## 3.4 枚举规范

禁止：

```ts
enum ConnectionStatus {}
```

使用：

```ts
export const CONNECTION_STATUS = {
  IDLE: 'idle',
  CONNECTED: 'connected',
} as const

export type ConnectionStatus =
  typeof CONNECTION_STATUS[keyof typeof CONNECTION_STATUS]
```

---

# 4. Vue 3 规范

## 4.1 必须使用 Composition API

禁止：

```ts
export default {
  data() {}
}
```

必须：

```vue
<script setup lang="ts">
</script>
```

---

## 4.2 组件命名规范

### 通用组件

```text
LButton.vue
LInput.vue
LVirtualTable.vue
```

### 业务组件

```text
ConnectionPanel.vue
SchemaTree.vue
```

---

## 4.3 Props 规范

必须：

```ts
interface Props {
  modelValue: string
}

const props = defineProps<Props>()
```

禁止：

```ts
defineProps({
  value: String
})
```

---

## 4.4 Emits 规范

必须显式声明：

```ts
const emit = defineEmits<{
  change: [value: string]
}>()
```

---

## 4.5 响应式规范

优先：

```ts
ref()
computed()
```

避免：

```ts
reactive({})
```

大型对象必须拆分状态。

---

## 4.6 组件职责规范

单组件不允许：

* 超过 500 行
* 同时承担 UI + 数据获取 + 状态管理
* 同时操作多个 Store

复杂逻辑必须抽离：

```text
composables/
services/
utils/
```

---

# 5. Pinia Store 规范

## 5.1 Store 命名

必须：

```ts
useConnectionStore
useEditorStore
```

---

## 5.2 Store 职责

Store 只允许：

* 状态
* 状态变更
* 业务协调

禁止：

* DOM操作
* UI渲染
* Monaco直接操作

---

## 5.3 Store 拆分规则

禁止超级 Store。

单 Store 状态超过：

* 15 个 state
* 20 个 action

必须拆分。

---

# 6. API 与 IPC 规范

## 6.1 IPC 必须统一封装

禁止：

```ts
invoke('execute_sql')
```

必须：

```ts
api.executeSql()
```

---

## 6.2 IPC 返回结构

统一：

```ts
interface ApiResponse<T> {
  success: boolean
  data?: T
  error?: AppError
}
```

---

## 6.3 错误处理规范

禁止：

```ts
catch (e) {
  console.log(e)
}
```

必须：

```ts
catch (error) {
  resultStore.setError(normalizeError(error))
}
```

---

# 7. Monaco Editor 规范

## 7.1 Monaco 生命周期

必须：

```ts
onMounted(init)
onBeforeUnmount(dispose)
```

禁止内存泄漏。

---

## 7.2 Editor 状态管理

禁止：

* Editor实例进入 Pinia
* 全局共享 editor 引用

必须局部管理。

---

## 7.3 SQL补全规范

补全数据来源：

```text
Schema Metadata
```

禁止硬编码 SQL keywords。

---

# 8. Result Table 规范

## 8.1 大数据集规则

超过：

```text
1000 行
```

必须使用：

```text
Virtual Scroll
```

---

## 8.2 禁止深度响应式

结果集必须：

```ts
shallowRef()
```

避免 Vue 深层代理大数组。

---

## 8.3 数据分页规则

禁止一次性加载：

```text
10万+ rows
```

必须支持：

* 分页
* 流式加载
* chunk append

---

# 9. Rust Backend 规范

## 9.1 驱动实现规范

所有驱动必须实现：

```rust
DbDriver
```

禁止驱动暴露私有实现。

---

## 9.2 async 规范

禁止：

```rust
std::thread::sleep
```

必须：

```rust
tokio::time::sleep
```

---

## 9.3 错误处理规范

禁止：

```rust
unwrap()
expect()
panic!()
```

生产代码必须：

```rust
Result<T, AppError>
```

---

## 9.4 ConnectionManager 规范

禁止：

* 长时间持有 Mutex
* 阻塞 DashMap
* 在锁内执行 IO

必须：

* 最小锁粒度
* 锁外执行 SQL

---

## 9.5 SQL执行规范

所有查询必须支持：

* timeout
* cancel
* tracing
* execution metrics

---

# 10. 数据库驱动规范

## 10.1 驱动能力矩阵

每个驱动必须声明：

```rust
pub struct DriverCapabilities {
    pub cancel_query: bool,
    pub transaction: bool,
    pub explain_plan: bool,
}
```

---

## 10.2 Metadata 查询规范

元数据查询必须：

* 使用系统 catalog
* 禁止 select *
* 限制返回字段

---

## 10.3 长连接规范

连接池必须：

* max lifetime
* idle timeout
* health check

---

# 11. UI/UX 规范

## 11.1 主题规范

禁止硬编码颜色：

错误：

```html
class="text-black"
```

正确：

```html
class="text-foreground"
```

---

## 11.2 Tailwind 规范

禁止：

```html
<div class="mt-[13px]">
```

必须使用设计系统 spacing。

---

## 11.3 Loading 规范

所有异步操作必须：

* loading 状态
* error 状态
* retry 能力

---

# 12. 性能规范

## 12.1 前端性能

禁止：

* 深层 watch
* watch 大数组
* computed 中大量循环

必须：

* memoization
* shallowRef
* 虚拟滚动

---

## 12.2 Rust 性能

必须：

* 零拷贝优先
* 避免 clone
* 避免 String 重复分配

---

## 12.3 IPC 性能

禁止：

* 大对象频繁 IPC
* 超大 JSON 序列化

必须：

* chunk transfer
* streaming

---

# 13. 日志规范

## 13.1 前端日志

统一：

```ts
logger.info()
logger.error()
```

禁止：

```ts
console.log()
```

生产环境禁止 console。

---

## 13.2 Rust 日志

必须：

```rust
tracing
```

禁止：

```rust
println!
```

---

## 13.3 日志字段

必须包含：

* connection_id
* execution_time
* sql_hash
* request_id

禁止记录明文密码。

---

# 14. 安全规范

## 14.1 密码存储

禁止：

```text
localStorage 明文密码
```

必须：

* OS Keychain
* 加密存储

---

## 14.2 SQL 安全

必须支持：

* SQL warning
* dangerous operation confirm

例如：

```sql
DELETE FROM users;
DROP DATABASE;
TRUNCATE TABLE;
```

---

## 14.3 IPC 安全

禁止：

* 任意 command invoke
* 未校验参数

---

# 15. 测试规范

## 15.1 前端测试

必须覆盖：

* Store
* composables
* 核心组件

---

## 15.2 Rust 测试

必须：

* 单元测试
* 驱动集成测试
* SQL执行测试

---

## 15.3 E2E 测试

必须覆盖：

* 建立连接
* 执行SQL

* 大结果集渲染

# 18. 禁止事项

严禁：

* any
* unwrap
* 超级组件
* 超级 Store
* console.log
* 跨模块直接引用内部文件
* SQL字符串拼接参数
* 同步阻塞 IO
* 未释放 Monaco 实例
* 深层 reactive 大对象

---

# 19. 推荐实践

推荐：

* use composables 拆业务
* use shallowRef 管理大数据
* Rust trait 抽象驱动
* IPC DTO 明确定义
* Result<T, AppError>
* tracing + metrics
* 虚拟滚动
* chunk loading
* schema cache

---

# 20. 目标质量标准

LinkBase 最终目标：

* 可支撑百万行结果集
* 查询不卡 UI
* 多连接稳定运行
* 驱动可插拔
* 前后端低耦合
* 可长期演进
* 企业级数据库工具质量标准
